== Sobre

Este é um modelo para repositórios de anotações em AsciiDoc. Ele não pressupõe um livro nem uma leitura linear: cada módulo representa uma coleção independente, com seu próprio índice, navegação e conjunto de páginas.

O mesmo conteúdo pode ser importado como componente Antora, visualizado em um site local e reunido em HTML, PDF e EPUB para arquivamento. O `doctype: book` usado pelo Asciidoctor é apenas o formato técnico necessário aos arquivos consolidados.

== Criar uma coleção

=== 1. Atualize a identidade

Edite a tabela e a seção Sobre acima, `modules/ROOT/pages/index.adoc`, `antora.yml` e `antora-playbook.yml`.

Centralize os metadados das coleções em `asciidoctor/publication.yml`:

[source,yaml]
----
author: A definir
isbn: ''

editions:
  my-notes:
    title: My Notes
    slug: my-notes
    lang: pt-BR
----

A chave de cada entrada deve ser idêntica ao diretório em `modules/`. O nome do módulo identifica a coleção; `lang`, como `pt-BR`, seleciona separadamente o perfil em `asciidoctor/support/attributes/`.

=== 2. Substitua o conteúdo

Cada módulo possui ao menos um índice, um arquivo de navegação e suas páginas:

[source,text]
----
modules/
├── ROOT/
│   ├── pages/index.adoc
│   └── assets/images/
├── my-notes/
│   ├── nav.adoc
│   └── pages/
└── other-notes/
    ├── nav.adoc
    └── pages/
----

Use slugs ASCII minúsculos. Quando houver uma ordem editorial útil, prefixe arquivos e diretórios com números, preferencialmente deixando intervalos para futuras inserções.

O primeiro item de cada `nav.adoc` deve ser o índice do próprio módulo. Mantenha a navegação lateral curta; páginas numerosas podem ser alcançadas por índices intermediários.

=== 3. Defina a ordem dos arquivos consolidados

Cada módulo possui um arquivo próprio em `asciidoctor/contents/<módulo>.adoc`. Isso permite que as coleções tenham páginas e estruturas diferentes:

[source,asciidoc]
----
include::../../modules/{edition-module}/pages/index.adoc[leveloffset=+1]
include::../../modules/{edition-module}/pages/0010-anotacao-exemplo.adoc[leveloffset=+1]
----

Imagens compartilhadas ficam em `modules/ROOT/assets/images/`. Imagens exclusivas de uma coleção podem ficar em `modules/<módulo>/assets/images/`; o Rake as inclui nos três formatos.

=== 4. Preserve a infraestrutura

Não é necessário modificar `Rakefile`, `asciidoctor/support`, `antora/`, `Gemfile`, `package.json` ou os lockfiles ao trocar somente as coleções.

== Executar localmente

=== Site Antora

Pré-requisitos: Git e Node.js 20 ou posterior.

[source,shell]
----
npm ci
npm start
----

O site é gerado em `build/site` e aberto no navegador.

=== HTML, PDF e EPUB

Pré-requisitos: Ruby 3.2 ou posterior e Bundler.

[source,shell]
----
bundle install
bundle exec rake
----

Os arquivos são gerados em `build/publications/<módulo>/`.

=== Validar antes de registrar mudanças

[source,shell]
----
npm exec -- antora antora-playbook.yml
bundle exec rake
----

== Publicar uma versão

O workflow `.github/workflows/release.yml` publica os arquivos de `build/publications` quando recebe uma tag anotada `vX.Y.Z`.

[source,shell]
----
git tag -a v1.0.0 -m "Primeira publicação"
git push origin v1.0.0
----

Use uma nova versão para cada atualização publicada; não mova nem reutilize tags existentes.

== Usar em outro site Antora

Adicione este repositório às fontes do playbook agregador. O Antora importa `antora.yml` e `modules/`; a infraestrutura local não se torna conteúdo do site.
